# Roadmap

Milestones 0–5 are implemented. Milestone 5 adds optional review-first local configuration assistance: header/schema CSV mapping suggestions, bounded issue explanations and ranking of locally supplied inspection candidates. Manual workflows remain complete without Ollama. This is not autonomous repair, correction learning or guaranteed workflow understanding.

0. Local library/editor, validation, SQLite migrations/revisions and actual desktop checks.
1. Dedicated Chromium/MV3 recording, session-bound validation, review and editable drafts.
2. Target provenance, preferred locators/read-only inspection, stable/shared inputs, deliberate checks, actionable validation and immutable evidence.
3. Supervised single-record execution, immutable pre-run snapshot, separate worker, per-origin approval, pause/resume/stop and durable honest outcomes. This deliberately preceded CSV to verify one row before multiplying actions.
4A. CSV preparation: maintained background parser, strict string preservation/bounds, explicit revision mapping/constants/trim, paged resolved validation, saved datasets/mappings and no-action preview. Completed and verified before connecting execution.
4B. Supervised sequential batches: exact immutable included/excluded rows/inputs/origins/settings, explicit approval, shared single-row engine, exclusive browser ownership, default pause-on-error, mandatory uncertain pause, durable row/step history, exception notes/filtering and protected JSON/CSV summaries. Only never-dispatched remaining rows may enter a new acknowledged review after confirmed worker exit. No automatic retry or restart.
5. Optional bounded local configuration assistance through existing loopback Ollama and `qwen3:8b-q4_K_M`, with explicit review/acceptance, deterministic offline guidance and no execution authority. The active-batch native close gap is also covered by actual Cancel/Confirm verification.

Stop after Milestone 5. The verified source snapshot may be committed and pushed under the user's explicit follow-up; no release, new model download, cloud/paid inference, reconciliation, automatic retry or executable model output is authorized. Possible later work requires separate authorization: user-assisted investigation/reconciliation design without automatic reruns; deeper history retention/pagination; broader screen-reader/DPI testing; installer/signing/distribution. No exactly-once or automatic reconciliation claim has been established.

Richer browser support, unattended operation, installers/signing and distribution require separate scope/authorization. Everyday browser profiles are never used; core functionality requires no model or paid service.
